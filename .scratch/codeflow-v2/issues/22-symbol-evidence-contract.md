# 22: 심볼 단위 코드 증거 데이터 계약 (어댑터 + 스키마 + fusion)

**What to build:** 단계 앵커가 문장 범위만이 아니라 그 문장을 감싸는 심볼(함수/클래스) 본문 범위와 심볼 이름을 함께 발행한다. 스캐너가 이미 계산한 메서드/클래스 경계를 재사용하고(스캔 로직 추가 없음), FlowSpec 스키마에는 선택적 필드로 추가해 하위 호환을 유지한다. fusion은 코드 렌즈를 view(심볼 본문, 상한 ~120줄, 초점 중심 여백) + focus(문장 줄) 구조로 결정적으로 유도하고, 심볼 범위가 없는 앵커는 문장 주변 ±12줄로 폴백한다.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [x] 어댑터가 심볼 범위 + 심볼 이름을 발행한다 (메서드 / 클래스 / 최상위 함수 케이스 테스트)
- [x] 스키마 확장 후 기존 픽스처 전부 재검증 통과 (하위 호환, 계약 깨지 않음)
- [x] fusion 렌즈가 view/focus를 결정적으로 유도한다 (상한 클램프 + 폴백 포함 go test)
