# CodeFlow 비즈니스 흐름 중심 전면 개편 설계 명세 (Specification)

- **문서 상태**: 승인 및 확정 (Approved Specification)
- **작성일**: 2026-08-21
- **핵심 목표**: 화면(Route) 중심 단편적 추적에서 **사용자의 도메인/비즈니스 흐름(Business Flow) 파악 중심**으로 전면 전환

---

## 1. 개요 및 핵심 원칙

### 1.1 핵심 가치 우선순위
1. **[1순위] 도메인 / 비즈니스 흐름 파악 (Business & Domain Flow)**:
   - 사용자가 애플리케이션에서 달성하고자 하는 비즈니스 목적, 유스케이스 단계, 조건 분기 결과 파악을 최우선 가치로 둔다.
2. **[2순위] 코드 흐름 및 구현 근거 추적 (Code Flow & Causal Verification)**:
   - 비즈니스 흐름을 뒷받침하는 핵심 소스코드, 상태 변이, 호출 경로 및 아키텍처 계층 인과 추적을 2순위 가치로 고정한다.

### 1.2 범위 통제 (Scope Boundary)
- 다종 언어/프레임워크 일반화(General Purpose) 확장은 추후로 유예한다.
- 현재는 Flutter/Dart 기반 애플리케이션의 실질적 비즈니스 플로우 분석 품질과 사용성에 100% 집중한다.

---

## 2. 설치 및 사용성 명세 (Zero-Friction DX)

### 2.1 쉬운 설치
- **단일 번들 설치**: Go Core와 Dart AOT Adapter가 하나의 패키지/스크립트로 로컬 환경(`HOME/.codeflow`)에 완전 자동 설정된다.
- 복잡한 빌드 단계나 사전 의존성 설정을 사용자에게 요구하지 않는다.

### 2.2 직관적 실행 및 탐색
- **비즈니스 플로우 중심 진입**:
  - `codeflow` 명령어 실행 시 프로젝트 내에서 자동 탐지된 주요 비즈니스 흐름 목록(회원가입, 인증, 결제 등)을 즉시 제공하고 인터랙티브하게 선택할 수 있다.
  - 라우트 AST 경로(`route:/...`)를 몰라도 도메인 키워드로 검색/실행(`codeflow run "회원가입"`)할 수 있다.
- **자동 비즈니스 여정 부트스트랩**:
  - 사전에 수동 등록된 JSON이 없더라도, 화면 간 전환 및 상태 변경 체인을 분석하여 첫 실행 시 "기본 비즈니스 여정"을 자동 구성하여 보여준다.

## 3. FlowView UI 및 정보 구조 명세

### 3.1 비주얼 테마: Black & White (Monochrome High-Contrast)
- 기존 FlowView 고유의 선명하고 절제된 흑백 스타일을 전면 유지한다.
- Primary: `#111` (Deep Ink), Background: `#fff` (Paper), Sub: `#f4f4f4` (Soft Gray), Border/Line: `#aaa`, `#ddd`.

### 3.2 컴포넌트별 레이아웃 및 기능 명세

```
+───────────────────────────────────────────────────────────────────────────────────+
| 🧭 1. 비즈니스 여정 네비게이션 (Business Journey Context)                           |
|  [● 확인됨] 회원가입 여정: 이메일 가입 > 약관 동의 > [인증 코드 발송] > 가입 완료            |
+───────────────────────────────────────────────────────────────────────────────────+
| 📌 2. 순차 타임라인 (좌측)   | 💻 3. Hero Code Lens (우측 상세 영역: 가로폭 ~80% 이상 확대)   |

|                             | 상태: unverified → code_sent  │  다음: route:/verify-code │
+───────────────────────────────────────────────────────────────────────────────────+
```

#### ① 비즈니스 여정 네비게이션 (Top)
- 현재 보고 있는 화면/단계가 전체 비즈니스 여정 중 어느 지점인지 한눈에 알 수 있는 상단 브레드크럼 및 진행 상태를 제공한다.

#### ② 타임라인 기반 흐름 추적 (Left Workbench)
- **보존**: 기존의 원형 마커, 얇은 연결선, 상태 변경 링, 분기 표기(`또는`, `분기 N`)를 유지한다.
- **개선**: 기술 중심 용어(Fact ID 등) 대신 사용자/비즈니스 행동 관점의 라벨을 최우선 노출한다.

#### ③ Hero Code Lens (Right Workbench - 대폭 확장)
- **화면 비중 확대**: 상세 영역의 80% 이상을 코드 뷰어에 배정하여 가로 스크롤과 비좁은 줄바꿈을 해소한다.
- **좌측 facts 패널 제거 및 슬림화**: 저가치 메타데이터(내부 AST 증거 해시, 코드 상태: clean 등)를 제거하고 공간을 확보한다.
- **핵심 줄 하이라이트**: 실행되는 핵심 비즈니스 로직 라인을 선명하게 강조한다.
- **VS Code 원클릭 연동**: 소스 위치 링크(`vscode://`)를 코드 툴바에 직관적으로 배치한다.

#### ④ 인라인 컴팩트 인과 바 (Inline Causal Bar)
- 코드 뷰 하단에 꼭 필요한 정보(`상태 변화: Before → After`, `다음 라우트 이동`)만 얇은 뱃지 바 형태로 컴팩트하게 배치한다.

#### ⑤ Architecture Map (코드 인과 지도 - 유지 및 가독성 고도화)
- **유지**: UI ➔ Presentation/Bloc ➔ Domain/UseCase ➔ State/Data 계층을 가로지르는 시각적 인과 지도 기능을 그대로 보존한다.
- **3단 동기화**: 타임라인 단계 ⇄ Hero Code Lens ⇄ Architecture Map 노드 간 양방향 클릭/스크롤/하이라이트 동기화를 유지한다.
- **가독성 개선**: 비즈니스 액션과 계층 흐름이 더 명확히 읽히도록 노드 라벨과 레인 배치를 정돈한다.

## 4. MCP / LLM 에이전트 인터페이스 명세

- **비즈니스 우선 응답 체계**:
  - LLM 도구 호출 시 저수준 AST 노드 대신 **"비즈니스 목적 및 결과 요약 ➔ 단계별 시나리오 ➔ 뒷받침 코드 근거"** 순서로 응답하도록 일관되게 구성한다.
- **도구 인터페이스 간소화**:
  - `get_business_flow` 등 도메인/비즈니스 흐름 중심의 단일화된 고수준 인터페이스를 제공한다.
