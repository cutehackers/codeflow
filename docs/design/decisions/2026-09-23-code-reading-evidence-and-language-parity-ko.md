# 코드 읽기 근거와 언어별 분석 결정

- Status: Proposed
- Created: 2026-09-23

- Source: 사용자 대화, 참고용 분석 엔진 개선안, 2026-09-21 계약과 Molycard 관찰

## 결정1. 화면에 열린 코드를 결과로 검증한다

요청·선택 근거·소스 범위가 같은 snapshot에 있어도 실제 CodeView가 다른 심볼을 열거나 비어 있으면 실패다. 모든 기본 항목의 실제 선택 결과를 검증한다. schema 검사만으로 완료 처리하는 대안은 화면 실패를 놓치므로 채택하지 않는다. 대표 코드 미표시 시 새 View를 저장하지 않으며 INV-01·02와 FA-01·02·08에 적용한다.

## 결정2. 문장 수집과 실행 확정을 분리한다

요청한 결과에 영향을 주는 중간 문장은 정확한 소스 범위와 함께 보존한다. 문장이 있다는 사실만으로 모든 분기와 `await` 후속 처리가 실행됐다고 선언하지 않는다. 참고안의 무조건적인 100% 수집과 모든 단계 인입 간선 요구는 예외·취소·도달 불가 문장을 잘못 연결할 수 있어 채택하지 않는다. 수집 범위는 fixture별 기대 코드 지점과 누락 여부로 검증하며 INV-03·04와 FA-03~05에 적용한다.

## 결정3. 언어별 문법 해석과 공통 후속 처리를 나눈다

Dart, TypeScript, Go adapter는 해당 언어의 AST에서 심볼·문장·직접 관계를 추출한다. 공통 계약은 근거 검증, 단계·관계 의미, curator의 포함 규칙, 저장·화면 동작을 맡는다. 단일 parser로 모든 언어를 정확히 해석하거나 정규식만으로 구현하는 대안은 문법 차이와 코드 범위 오류 때문에 채택하지 않는다. 공통 계약 변경은 공개 protocol과 과거 View 호환성을 검토해야 한다. INV-05·06과 FA-06~08에 적용한다.

## 결정4. 언어별 완결 경로를 별도로 확인한다

TypeScript와 Go는 각각 요청부터 CodeView까지 독립적으로 검증한다. 공통 기반만 구축하고 언어별 화면 결과를 생략하는 대안은 사용자 가치를 증명하지 못한다. 한 언어의 분석 실패가 다른 언어의 View를 바꾸지 않아야 하며 FA-06·07에 적용한다.

## 후속 확인

구현 전 현재 작업 트리의 Molycard 재현 결과를 갱신한다. 새 필드나 저장 migration이 필요해지면 consumer 목록과 호환 방안을 별도 검토한다. 이 결정 기록은 기존 계약·결정 기록을 수정하거나 폐기하지 않는다.
