# 처리 구간과 코드 블록 읽기의 구현 결정

- Status: Proposed
- Created: 2026-09-30
- Contract: [요청 흐름 코드 블록 읽기](../specs/2026-09-30-requested-flow-code-block-reading-ko.md)
- Source: 사용자 수정 지시, 기존 승인 계약, commit `76821b3`의 화면·데이터·검사 대조

## 결정1. 구간과 코드 블록을 개요의 읽기 단위로 사용한다

현재 선별 지점 목록과 단일 step 선택으로는 여러 문장이 수행하는 처리를 함께 읽을 수 없다. 구간은 처리 목적을 설명하고 포함 단계와 실제 소스 블록을 가진다. 중앙은 선택 구간의 블록들을 표시한다. 단순 문장 선별 확대, 함수 전체 무조건 표시, frame 이름 변경은 목적과 실제 구현의 대응을 보장하지 못해 채택하지 않는다. 기존 상세 탐색은 보존한다. 영향: FA-01·02·04, 정확한 소스와 전체 상세 보존.

## 결정2. 의미 제안과 사실 검증을 기존 경로 안에서 구분한다

기존 에이전트가 구간을 제안하고 서버가 단계·관계·snapshot·소스를 검증한다. 별도 범용 묶기 엔진이나 모델 서비스를 만들지 않는다. UI에서 코드 근접성으로 묶는 대안은 근거 없는 처리 목적과 순서를 만들 수 있어 채택하지 않는다. 기존 View에 선택적 버전 관리 개요를 더하므로 저장·HTTP·MCP 소비자를 함께 검사해야 한다. 영향: FA-01·03·05, 불변 View와 보안 규칙. 후속: 티켓1에서 schema 선언과 소스 복원 가능성을 검증한다.

## 결정3. 지원하지 않는 생성 경로를 성공으로 표시하지 않는다

브라우저 직접 분석은 현재 구간 생성자를 호출하지 않는다. 새 모델 서비스를 추가하는 대신 개요 미생성을 명시하고 상세 탐색은 사용자가 선택한다. 에이전트 요청에서는 구간 생성부터 최종 View 열기까지 책임진다. 조용히 기존 상세를 여는 대안은 사용자가 개선 여부를 판단할 수 없어 채택하지 않는다. 브라우저 단독 자동 개요는 이번 제공 범위가 아니며 상위 계약 전체 완료로 주장하지 않는다. 영향: FA-01·06, 현재 View·baseline 보존. 후속: 티켓3에서 실제 배포 화면까지 확인한다.
