# Live 처리 흐름 분기 UX 검증과 최종 제안

상태: 채택하지 않은 이전 검토 기록. 사용자 검토에서 화살표 분기의 코드 이해 기여가 부족하고 카드의 텍스트가 과도하다는 문제가 제기됐다. 아래 기하·동작 검증은 사용성 검증이나 제품 채택 근거로 취급하지 않는다. 비교용 HTML과 이미지 3개는 작업 공간에서 제거하고 임시 보관했다. 기존 Live 화면과 이전 프리뷰는 유지했다.

2026-09-09. 제품 코드에는 적용하지 않은 화면 검증 결과다. 설명용 분기 데이터를 사용했으며 실제 분석 데이터의 순서·조건 정확성을 검증한 것은 아니다.

## 결정1. 적응형 분기 개요와 선택 경로를 채택

중앙에 여유가 있는 2~3갈래는 조건별 경로와 합류를 연결선으로 함께 표시한다. 더 많은 분기 또는 좁은 중앙 영역에서는 모든 조건과 도착점을 세로 목록으로 유지하고 선택한 경로의 내부 처리를 펼친다. 화면 전체 너비가 아닌 중앙 가용 너비로 판단한다. 프로토타입은 경로당 240px을 기준으로 삼았으며, 최종 기준은 실제 라벨 길이와 사용자 평가로 조정한다.

왼쪽 주요 처리 단계, 중앙 보기 전환, 우측 선택 맥락을 유지한다. 탐색 선택은 실행 경로 확정이 아니다. 코드 보기로 전환해도 선택 조건을 유지한다. 모바일에서는 상세가 전체 목록 아래로 밀리지 않도록 선택한 조건 바로 아래에 상세와 코드 진입 버튼을 둔다.

## 검증1. 비교 구성

| 구성 | 관찰 | 판단 |
|---|---|---|
| A. 전체 경로 가로 펼침 | 5·8갈래는 넓은 화면에서도 중앙 내부 가로 스크롤 필요 | 단순하고 폭이 충분한 분기에 한정 |
| B. 조건별 세로 목록과 모든 상세 | 가로 넘침은 없지만 개요와 상세가 반복되고 페이지가 길어짐 | 기본 구성으로 채택하지 않음 |
| C. 적응형 개요와 선택 상세 | 조건과 도착점 전체를 유지하면서 선택한 내부 처리만 노출 | 권장 |

프로토타입 스킬에 따라 같은 Live 샘플 화면 안에서 세 구성을 비교했다. 하단 전환 버튼 또는 URL의 `variant=A`, `variant=B`, `variant=C`로 구성 변경이 가능하다. 소스·분기 데이터는 설명용이며 제품 호출을 하지 않는다. 저장소 규칙에 따라 브랜치 생성·커밋·제품 반영은 수행하지 않았다.

## 검증2. 범위와 방법

Chromium에서 320·390·768·1440·1920px, 3개 구성, 6개 사례를 조합해 90개 화면 상태를 점검했다. 사례는 3갈래, 기본 경로를 포함한 5갈래, 긴 라벨의 8갈래, 한 단계 중첩 분기, 부분 합류·오류 종료·이후 미확인, 병렬 시작·전체 대기다.

페이지와 중앙 그래프의 가로 넘침, 생성된 연결선 수, 조건 목록 수, 브라우저 오류를 확인했다. 3갈래 데스크톱, 5갈래 데스크톱, 8갈래 모바일 스크린샷을 직접 확인했다. 선택한 7번째 조건의 코드 보기 왕복과 URL 구성 복원도 확인했다.

최종 점검 결과: 90개 상태에서 브라우저 오류와 페이지 가로 넘침은 없었다. A의 30개 상태 중 22개에서 그래프 내부 가로 스크롤이 필요했다. B·C는 각각 30개 상태에서 내부 가로 넘침이 없었다. 코드 보기 왕복 후 7번째 조건 선택과 구성 URL 복원이 유지됐다. 이는 기하·동작 점검 수치이며 사용자 과제 성공률이 아니다.

이 검증은 임의의 복잡한 그래프에 대한 교차선 제거, 모든 중첩 깊이, 모든 스크린리더·브라우저, 실제 사용자 이해 속도를 보장하지 않는다. 중첩 내부는 조건별 텍스트 경로로 표현한 한 단계 사례이며 임의 깊이의 연결선 배치 검증은 미완료다.

## 결정2. 의미별 표시 규칙

| 관계 | 표시 |
|---|---|
| 조건에 따른 선택 | 판단 지점에서 조건 라벨로 갈라짐. 배타적 선택인지 여러 조건이 동시에 성립하는지 명시 |
| 정상 합류 | 실제로 합류하는 경로만 공통 후속 처리로 연결 |
| 조기 반환·오류 종료 | 해당 경로 안에서 종료. 정상 합류선 생성 금지 |
| 이후 미확인 | 미확인 도착점. 종료로 단정하지 않음 |
| 중첩 분기 | 상위 조건을 유지한 내부 묶음. 복잡해지면 해당 묶음을 선택해 상세 탐색 |
| 병렬 처리 | 모든 작업 실행 및 대기 조건 표시. 하나를 선택하는 분기와 구분 |

흑백에서 방향 화살표와 명시적 조건·도착점이 의미를 전달해야 한다. 선택 여부는 선 굵기와 테두리로 보완하며 색상만으로 정보를 구분하지 않는다. 모든 조건의 존재는 유지하되 내부 설명은 점진적으로 공개한다. 이는 [NN/g의 progressive disclosure 지침](https://www.nngroup.com/articles/progressive-disclosure/)과 일치한다. 좁은 화면에서 주변 정보까지 가로 스크롤에 종속시키지 않는 방향은 [W3C Reflow 설명](https://www.w3.org/WAI/WCAG21/Understanding/reflow.html)을 참고했다. 이 자료가 본 제품의 사용자 성능 향상을 입증하지는 않는다.

## 결정3. 제품 적용 조건

화면 개선만으로 현재 함수 목록을 실행 순서도로 바꾸지 않는다. 처리 행동별 소스 위치, 선후 관계, 조건과 대상의 대응, 합류 위치·대기 조건, 반환·종료·미확인 구분이 근거와 함께 제공되어야 한다. 분석에 없는 관계를 라벨이나 연결선으로 생성하지 않는다.

최종 제품 구현 전에 실제 코드 사례로 조건에서 도착점 찾기, 종료 경로 구분하기, 관련 소스로 이동하기를 사용자에게 수행하게 하고 정답률·소요 시간·오클릭을 기존 화면과 비교한다. 다중 분기에서 개선이 확인되지 않으면 상세 공개 방식과 라벨을 재조정한다. 현재 결론은 화면 구조의 적합성 판단이며 코드 인지력 향상 실증은 아니다.

## 산출물

비교용 화면 생성물은 사용자 요청에 따라 제거했다. 이 문서는 이전 검증 범위와 한계를 기록하기 위해 보존한다.
