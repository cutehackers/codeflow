# CodeFlow 기능 및 프롬프트 가이드

이 문서는 사용자가 CodeFlow에 무엇을 요청할 수 있고, AI 에이전트가 CodeFlow MCP 도구를 통해 어떤 결과를 제공하는지 설명한다. CodeFlow skill은 자동 호출되지 않으므로 모든 프롬프트에서 `$codeflow`를 명시한다.

---

## 1. 사용 전 준비

CodeFlow의 전체 기능을 사용하려면 Core 바이너리, 언어 어댑터, MCP 서버, CodeFlow 스킬이 설치되어 있어야 한다.

```sh
curl -fsSL https://raw.githubusercontent.com/cutehackers/codeflow/main/scripts/install.sh | bash
```

설치 후 AI 에이전트 앱을 재시작하거나 새 task를 열고 대상 프로젝트 루트의 환경 무결성을 점검한다.

```sh
$HOME/.local/bin/codeflow doctor <프로젝트-루트>
```

`Workspace not initialized`가 표시되면 한 번만 초기화한다.

```sh
$HOME/.local/bin/codeflow init <프로젝트-루트>
```

항상 `pubspec.yaml`, `package.json`처럼 프로젝트 종류를 식별할 수 있는 매니페스트 파일이 위치한 프로젝트 루트를 대상으로 사용한다. 특정 하위 디렉터리만 타깃으로 전달하지 않는다.

---

## 2. 기존 기능의 전체 흐름 이해 (FlowView Storyboard)

CodeFlow는 UI 이벤트, API 요청, 라우트 또는 시스템 이벤트와 같은 시작점부터 비즈니스 로직과 데이터/외부 연동 계층까지의 핵심 흐름을 추적한다. 각 단계는 실제 코드 위치와 검증된 앵커(Fact Anchor)에 연결되며, 4~7개 핵심 비즈니스 관문으로 큐레이션된 스토리보드와 1:N 실행 타임라인으로 제공된다.

### 프롬프트 예제

```text
$codeflow 이 프로젝트의 이메일 회원가입 기능이 시작부터 완료까지 어떤 코드 경로로 실행되는지 분석해줘.
```

```text
$codeflow 장바구니에서 결제 버튼을 누른 뒤 주문이 저장되고 외부 결제 서비스가 호출될 때까지의 전체 코드 흐름을 보여줘.
```

```text
$codeflow 로그인 화면의 제출 처리 함수에서 시작해 상태가 어떻게 바뀌고 어떤 조건과 데이터 저장 코드를 거치는지 분석해줘.
```

```text
$codeflow 이 코드 흐름을 FlowView 검토 화면으로 열어줘.
```

### 제공 결과

- 자연어 질의에 매칭되는 후보 흐름 및 진입점 탐색 (`harvest_flows`)
- 특정 entry symbol에 대한 온디맨드 AST 슬라이싱 및 흐름 발행 (`analyze_flow`)
- 4~7개 핵심 관문(`FlowSequenceFrame`: `entry`, `decision`, `process`, `effect`, `result`, `boundary`) 스토리보드
- 각 관문 내 1:N 미시 실행 타임라인(`SemanticStep`: `call`, `guard`, `mutation`, `result`)
- 검증된 소스 코드 앵커 기반의 3열 FlowView 웹 워크벤치 URL (`open_review`)
- 고밀도 압축 페이로드 조회 (`get_flow_payload`)

## 3. 명시적 재분석 (Explicit Re-analysis)

FlowView는 개발자의 읽기 위치, 펼쳐진 아코디언 상태, 선택한 장면을 보호하기 위해 백그라운드 파일 감시자(watcher)나 편집 이벤트에 따라 화면을 자동으로 교체하지 않는다. 사용자가 명시적으로 재분석을 요청했을 때만 최신 불변 스냅샷을 1회성으로 분석하고, 성공한 결과만 안전하게 화면에 반영한다.

### 프롬프트 예제

```text
$codeflow 방금 수정한 결제 처리 코드의 최신 상태를 다시 분석해서 FlowView 화면을 갱신해줘.
```

```text
$codeflow 회원가입 로직 변경 사항을 반영해서 스토리보드를 새로고침해줘.
```

### 제공 결과

- 동일 진입점에 대한 최신 코드 기반 단일 스냅샷 1회성 재분석
- 성공한 결과만 원자적으로 화면 전환 (실패, 취소 시 기존 화면 및 읽기 위치 유지)
- 선택된 장면의 코드 앵커 및 1:N 실행 타임라인 동기화

## 4. 기준선 기반 변경 전후 비교 (Baseline Comparison)

사용자가 명시적으로 선택한 기준선(Baseline)과 현재 분석 결과 사이의 의미적 차이를 비교한다.

### 프롬프트 예제

```text
$codeflow 이번 수정 전과 후에 로그인 실패 처리 동작이 어떻게 달라졌는지 비교해줘.
```

```text
$codeflow 이전 분석 기준선과 현재 분석 결과를 비교해서 추가·변경·제거된 비즈니스 관문과 코드 근거를 구분해줘.
```

### 제공 결과

- 추가된 비즈니스 관문 및 실행 단계
- 변경된 조건 및 상태 변경
- 제거된 호출 경로
- 동작은 동일하나 소스 코드 앵커만 이동한 항목
- 사용자가 선택한 기준선과 현재 분석 간의 정밀 대조

---

## 5. 직접 관계망 및 영향 검토 (Blast Radius Radar)

선택된 비즈니스 관문과 코드 앵커에서 직접 연결된 호출자/피호출자, 상태 변경 및 관련 테스트를 탐색한다.

### 프롬프트 예제

```text
$codeflow PaymentService.capture 결제 승인 함수의 변경이 어떤 직접 호출 코드, 상태, 외부 서비스와 테스트에 영향을 주는지 분석해줘.
```

```text
$codeflow 선택한 관문과 직접 연결된 테스트 파일과 호출 지점 목록을 보여줘.
```

### 제공 결과

- 동일 스냅샷 기반의 검증된 1단계 직접 호출(Direct Callers / Callees)
- 상태 변경(State Mutations) 및 외부 부수 효과(External Effects)
- 연관 단위/통합 테스트 스팬
- 추측에 기반한 전역 런타임 영향 추정 배제 (Anti-Hallucination)

## 6. 미확인 영역 및 분석 경계 파악 (Unknowns & Boundaries)

동적 디스패치, 인터페이스 다형성, 외부 라이브러리 경계 등으로 인해 정적 분석이 단절된 지점을 파악한다.

### 프롬프트 예제

```text
$codeflow 이 프로젝트에서 정적 분석으로 확인되지 않은 호출 결손이나 분석 경계 지점을 보고해줘.
```

```text
$codeflow 분석된 코드 흐름 중 외부 시스템 연동이나 동적 디스패치로 인해 추적이 중단된 위치를 알려줘.
```

### 제공 결과

- `report_unknowns` 도구를 통한 미확정 호출 결손 목록
- `unresolved_dynamic`, 누락된 타입 및 외부 API 경계 보고
- 추측 대신 명직하게 드러난 `boundary` 관문과 그 사유

## 7. 선택 기능: Semantic Labeling (SLMLabeler)

로컬 경량 언어 모델(Ollama/vLLM 등)이 활성화되어 있는 경우, 검증된 FlowSequence 관문에 사람이 읽기 쉬운 한국어 비즈니스 라벨을 비동기로 제안받을 수 있다.

### 프롬프트 예제

```text
$codeflow 현재 검증된 코드 흐름의 각 관문에 알기 쉬운 비즈니스 요약 라벨을 붙여줘.
```

```text
$codeflow 이 관문 설명이 어떤 코드 구조와 함수 호출을 근거로 제안되었는지 확인해줘.
```

- **무장애 폴백**: 로컬 모델이 없거나 타임아웃(500ms)이 발생하면 에러 없이 정적 AST 사실 텍스트를 그대로 유지한다.
- **표시 전용 제안**: 모델이 제안한 라벨은 표시 전용(Display Proposal)이며, 검증된 코드 팩트나 앵커를 변경하지 않는다.

## 8. 공식 8대 핵심 MCP 도구 대응표

다음 표는 사용자 기능과 이를 수행하는 CodeFlow 공식 8대 핵심 MCP 도구를 연결한다. 사용자는 자연어로 요청하며, 도구 이름을 직접 지정할 필요가 없다.

| 사용자 목적 | 공식 핵심 MCP 도구 | 설명 |
|---|---|---|
| 후보 흐름 찾기 | `harvest_flows` | 자연어 질의(`query`) 또는 의도 신호로 진입점 후보 탐색 |
| 특정 진입점 즉시 분석 | `analyze_flow` | 지정한 진입점 심볼을 정적 슬라이싱하여 FlowSpec 발행 |
| Core Flow 검증 및 발행 | `publish_core_flow` | 에이전트가 작성한 중간 아티팩트의 앵커 무결성을 검증하고 발행 |
| 발행된 흐름 상세 조회 | `get_flow_payload` | FlowSpec JSON 및 ~500토큰 고밀도 압축 페이로드 조회 |
| 구조화된 flow draft 제출 | `submit_flow_draft` | 검증된 앵커가 포함된 구조화된 세션 여정 초안 제출 |
| 단계 이름 및 규칙 승인 | `approve_step` | 특정 단계의 비즈니스 명칭 및 규칙을 인플레이스로 승인 |
| 미확인 경계 및 결손 조회 | `report_unknowns` | 확인되지 않은 호출 결손, 모호한 디스패치 및 분석 경계 목록 조회 |
| FlowView 검토 화면 열기 | `open_review` | FlowView 브라우저 URL(인증 토큰 포함) 지연 생성 및 반환 |

## 9. 결과를 해석하는 기준

- **`Fact Anchor`**: 코드 상대 경로, 바이트 오프셋, SHA-256 해시로 증명된 실제 코드 위치
- **`verified`**: 현재 스냅샷 코드와 100% 일치하며 모든 앵커가 검증된 상태
- **`stale`**: 스냅샷 생성 이후 소스 코드가 수정되어 재분석이 필요한 상태
- **`orphaned`**: 코드 수정으로 해당 심볼이나 함수가 삭제되거나 이동한 상태
- **`unknown / boundary`**: 동적 디스패치나 분석 범위 밖이라 추적할 수 없는 지점으로 정직하게 격리된 상태

> ⚠️ **Anti-Telemetry Guard**: 컴파일러 에포크, 파일 변경 지연 시간, 내부 결재 플래그 등 엔진 내부 텔레메트리는 사용자 화면과 설명에 노출하지 않으며, 오직 비즈니스 관문과 검증된 코드 근거만을 명확하게 제시합니다.
